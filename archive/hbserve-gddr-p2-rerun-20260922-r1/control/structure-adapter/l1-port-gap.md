# R4 L1 port feasibility — source-only gap assessment

**R4 L1 has not been ported.** The closed structure adapter still runs this side's 32 KiB / 64-way LRU, raw-VA linear set indexing and existing asynchronous sector-validity/ticket model. Its 34/272 hit settings and new L2 software geometry do not constitute the shared R4 L1 model. This assessment only read existing files; no compilation, simulation or configuration change was performed.

A small isolated implementation is feasible, but **not by replacing the header**. The minimum safe work is a local L1-policy extension plus a history allocation resolver and per-kernel configuration bridge. Two missing inputs/joins prevent claiming complete R4 admission now: allocation-generation-relative addresses are not in the current transactions, and the current dispatch/timeline has no per-kernel observed shared-carveout field.

## Concrete boundaries

1. **Hash/address identity.** Local `PerSmL1Access` has SM, `allocation_id`, raw canonical line and requested sector mask (`per_sm_l1.h:71`), and `memory.h:2116` constructs it from the cache key. It has no allocation base/offset. Current bindings deliberately emit `{1, rawVA}` for all global roles (e.g. elementwise `bridge.h:60–63`); therefore matrix ID 1 is not an actual driver allocation identity, and the global service-map base is not an allocation base. Using either would implement a different hash and break cross-role alias meaning.

   Shared `llm_l1_adapter.h:45–55,73–74` resolves each non-bypassed line through a live **CUDA driver allocation generation**, then gives L1 a separate allocation ID and `line - allocation.base`. The hash consumes aligned uint32-relative byte offsets and checks one stable base per ID (`shared per_sm_l1.h:675–698`). Current saved timeline does contain 150 allocation API observations, including successful synchronous `cuMemAlloc_v2` base/bytes/generation and frees; root runtime presently records them as metadata (`history_runtime-r3.cpp:58–59`) rather than maintaining a lookup table. A resolver can be attached there without changing L2 cache keys or HBF mapping. Its validation must reject unresolved, overlapping, freed/reused-generation, unaligned and >UINT32_MAX offsets before L1 mutation. Typed tensor/storage roots are not an equivalent replacement for the driver's allocation base. Preserve raw-VA aliases; do not rename the L2 tags into new allocation IDs.

2. **CLOCK + hash2 policy slice, not the whole shared sector model.** Port the explicit replacement/hash enums, exact uint32 hash arithmetic, per-set hand and per-line reference bit. Keep this side's `requested_sector_mask`/`fill_sector_mask`, original immutable ticket identity, actual delayed completion, ready promotion and stale-ticket retirement. Update all three set-index paths: `locate`, `same_negative_read` and `remember_negative_read`; the latter two currently hardcode linear indexing (`local per_sm_l1.h:243–257`). Include allocation/relative-offset identity and a layout epoch in negative memos, and invalidate host ready-prefix certifications on configuration changes.

   The shared implementation also changes behavior beyond CLOCK: byte-known store state, `sector32`/write-allocation support, dirty protection and **pending-ticket victim exclusion**. Its full-set/no-eligible case forwards without allocating a ticket (`shared per_sm_l1.h:495–507,699–724`); the local model may evict a pending reservation and later retire its stale ticket. This is an actual asynchronous semantic difference even though the shared serial caller rarely exposes it. Retaining local pending semantics yields an explicitly labeled **R4 hash/CLOCK adaptation**, not exact shared asynchronous equivalence. Importing shared pending protection requires a separate reservation-failure case, counters and ticket-closure contract; it cannot silently preserve `all nonbypass misses == issued tickets`. Store byte-validity/write-allocation/dirty protection need not be imported for the selected store-bypass, read-filter scope and must remain disabled.

3. **Capacity configuration at an existing quiescent boundary.** Local L1 only has `begin_kernel()`/`flush_all` (`local per_sm_l1.h:377,534`); no resize API. Add a narrow L2 facade that requires actual L2/backend quiescence and zero live L1 tickets, then allocates replacement line/epoch/hand arrays before mutation, preserves cumulative statistics and monotonic ticket/generation counters, clears L1 only, advances layout/SM promotion epochs, and records a capacity-change observation. Invoke once before the existing per-kernel `begin_kernel`; do not recreate L2/backend, reset clock, or double-count flushes. Shared `configure_capacity_bytes_per_sm` (`shared per_sm_l1.h:296–335`) supplies the design, but its layout/memo protection must be ported with it. Current runtime already enforces operation-boundary quiescence and ends each kernel before binding destruction, so this integration point exists.

4. **Per-kernel capacity evidence.** Shared R4 fixes 16 sets, 128B lines, effective capacity scale 1.062 and variable integer ways: observed shared carveouts 32/64/100 KiB produce L1 100/66/28 KiB with 50/33/14 ways. The LLM adapter additionally allows 8/16 KiB shared → 126/118 KiB L1 with 63/59 ways, explicitly **uncalibrated extrapolations** (`ada_r4_profile.h:8–39`; `llm_l1_adapter.h:20–27`). The saved current 2,426-kernel timeline has zero `observed_shared_bytes` fields, and regular dispatch entries do not include a shared-carveout witness. Static/dynamic per-CTA shared usage, preferred carveout and source occupancy are not the observed per-SM hardware partition. Need a pinned same-cohort per-kernel witness join, or explicitly selected assumed/extrapolated bins with no observed/admitted claim. Do not derive the carveout merely by multiplying dynamic shared bytes by modeled resident CTAs.

## Smallest required tests before integration

* Default/OFF exact regression against the closed async sector-L1 component, including every old field; preserve current q1/q8 work/dirty/backend accounting.
* Pure read-filter hash/CLOCK and each declared capacity bin against the shared frozen serial implementation; allocation-relative relocation invariance plus >4 GiB/unknown-generation rejection. Classify/retry must not advance CLOCK.
* Actual asynchronous independent/overlapping tickets, partial sector promotion, L2-hit delayed completion, pending-way pressure and stale completion; test the chosen explicit reservation policy, not an assumed serial equivalent.
* Reconfigure only at quiescence: zero-live acceptance, live-ticket rejection, cumulative statistics, monotonic generation/IDs, old memo rejection, valid callback lifetime, and no L2/DRAM flush. Test allocation free/reuse through real saved timeline records without pretending host free is device completion.
* One short current Tiny/Fine/API history with the new resolver, L1 masks and per-kernel capacity provenance; preserve accepted source bytes, raw address aliases, dependencies and full callback closure. No full-run revalidation is needed to discover these interface gaps.

**Decision:** keep this port as the next required isolated change. It is not part of the five-window structure run currently being timed. The immediately reusable pieces are the exact hash/CLOCK arithmetic and capacity formula; allocation-history plumbing, observed-carveout admission and async pending-victim qualification are real work still to do. R4 is an empirical serial-read model extrapolated to an LLM, not measured hardware occupancy or timing.
