# RTX 4000 Ada 第二轮缓存候选配置与验证

更新时间：2026-09-22（服务器日期）。当前状态：**已完成配置生成与第二轮测试；候选配置仅部分通过流量验证，尚未成为全面匹配硬件的正式配置。**

本文件中的 GPU（Graphics Processing Unit）指 RTX 4000 Ada 图形处理器；SM（Streaming Multiprocessor）指流式多处理器；CTA（Cooperative Thread Array）指一个线程块。L1/L2 是一级/二级缓存；DRAM（Dynamic Random-Access Memory）是显存；sector 是对齐 32 字节的计数单位。KiB=1024 字节，MiB=1048576 字节。NCU（NVIDIA Nsight Compute）提供实机性能计数，SASS 指 GPU 机器指令汇编，CUDA（Compute Unified Device Architecture）指 NVIDIA 计算平台。MSHR（Miss Status Holding Register）是未完成缓存未命中请求的跟踪资源；LRU（Least Recently Used）淘汰最久未访问的缓存行；FIFO（First In First Out）按分配先后淘汰缓存行。这些策略和数量在本组文件中是有效模型假设，并非硬件实现声明。

JSON（JavaScript Object Notation）用于结构化配置与结果；CSV（Comma-Separated Values）用于逐条件表格；SHA-256 是文件完整性散列。r1/r2 分别指第一轮硬件校正和本轮配置回放；目录前缀 00–06 只是配置编号，没有准确度等级含义。cycle 是设备或模型时钟周期。访问命中/未命中计数均限定为全局读取；不将输出写入、重试次数或指令缓存访问混入分母。

## 配置文件与使用边界

每个子目录包含完整 `gpgpusim.config` 和 `trace.config`，可传给 Accel-Sim 的两个 `-config` 参数。未覆盖原 tuner 配置或 memgen 工作分支。实际参数来源和全部差异记录在 `parameter_contract.json`，不是声称 memgen 已实现的加载接口。

| 目录 | 改动与适用条件 |
|---|---|
| 00_tuner_baseline | 原 tuner 参数对照，零动态共享内存时模型 L1 为 128 KiB |
| 01_measured_adaptive | 共享内存选项改为 32,64,100 KiB；零动态共享内存时模型 L1 为 96 KiB；L2 附加延迟由 238 四舍五入为 239 cycles |
| 02_shared64 | 强制使用 64 KiB 共享内存划分，模型 L1 为 64 KiB；仅用于 NCU 确认该划分且线程块总共享内存需求不超 64 KiB 的内核 |
| 03_shared100 | 强制使用 100 KiB 共享内存划分，模型 L1 为 28 KiB；仅用于 NCU 确认该划分的内核 |
| 04_l1_fifo | 在 01 上只把 L1 替换由 LRU 改成 FIFO |
| 05_l1_mshr96 | 在 01 上只把 L1 MSHR 条目数 384 改为 96 |
| 06_l1_mshr768 | 在 01 上只把 L1 MSHR 条目数 384 改为 768 |

共享内存首选划分是 CUDA 内核属性，当前 SASS trace 没有完整编码该信息。必须根据实际观测选配置；01 并不能自动重现所有首选划分。配置中的 `S:4:128:64` 初始化字符串不是最终 32 KiB 容量：模拟器按 128 KiB 统一缓存重新计算相联度，本轮真实回放确认得到 128/96/64/28 KiB。这里的集合数、相联度和物理地址哈希仍是模型选择。

延迟沿用 r1 空载、未锁频的指针追逐：L1 34.0044、L2 272.68445、显存 596.228 cycles。新增配置使用 L1 基础 34、L2 **附加** 239、显存**附加** 324；不是把总延迟填入附加流水级。流量通过不能代表这些时延已通过端到端验证。L2 40 MiB、sector 32 字节等已有约束继续保留。约 19.963 MiB 的条件脏数据保留拟合没有写入全局配置，因为 r1 顺序对照否定了无条件使用。

## 完成的测试

独占物理 GPU 2 完成硬件阶段后已释放设备。新集合有 48 个容量条件：3 个共享内存首选值 × 8 个工作集（20/28/40/56/72/88/104/120 KiB）× 2 种顺序；每个内核扫描 8 遍。另有 18 个热点条件：3 个首选值 × 3 个热点大小（4/12/24 KiB）× 是否在污染流之间刷新热点；污染数据共 112 KiB。这些条件在 r2 模型比较前声明，未用本轮测量反向挑选容量。

- 新条件 66 个，各执行 5 次原生数值检查，共 330 次，全部正确；memcheck（非法内存访问）与 initcheck（未初始化读取）两项检查为零错误。
- 新条件各采集 5 次 NCU，共 330 次；另复测 r1 并发集合 72 条件 × 3 次，共 216 次，合计 546 次 NCU 内核采集。应用重放，冷缓存，未锁频。
- 新集合 41 / 66 个条件的读取计数组稳定；DRAM 读 44 / 66、写 66 / 66 稳定。并发复测读取计数组 72 / 72 稳定。稳定阈值是重复极差 ≤ max(2 个原始计数单位，中位数的 2%)，不是硬件结构识别结论。
- 地址 oracle（仅由地址及有效线程计算的独立预测）验证 L1 读 sector：330 / 330 次精确；实际共享内存划分：330 / 330 次符合 32/64/100 KiB。
- 生成 66 个新条件和 6 个并发条件的 SASS trace；222 次独立模拟器进程全部完成一个且仅一个内核，并验证退出状态、完整内核计数和流量字段。未把仅解析配置后退出视为完成。
- 每次模拟器进程以空缓存开始，回放清单不含主机复制预填，匹配 NCU 冷缓存条件。原始完整 trace 清单保留。模拟器二进制复制到本轮目录，未修改其他任务正在使用的模拟器或工作分支。

## 完整集合误差

WAPE（Weighted Absolute Percentage Error，加权绝对百分比误差）= 各条件预测与实测中位数的绝对误差之和 / 实测中位数之和 ×100%。所有 66 个条件都保留，包括不稳定容量边界。每个条件的权重由其计数决定，不是各百分比的简单平均。右列通过标准为绝对误差 ≤ max(2 sectors, 实测中位数×2%)。

| 指标 | 原配置 WAPE | 按实际共享划分选候选的 WAPE | 候选通过条件 |
|---|---:|---:|---:|
| L1 读访问 | 0.00% | 0.00% | 66 / 66 |
| L1 读命中 | 97.96% | 22.61% | 42 / 66 |
| L2 读访问 | 68.38% | 15.78% | 43 / 66 |
| L2 读命中 | 99.40% | 22.94% | 42 / 66 |
| L2 读未命中 | 0.00% | 0.00% | 66 / 66 |

逐行结果在 `../analysis/comparison.csv` 和 `comparison_rows.json`，完整硬件重复在 `hardware_aggregates.json`，摘要在 `summary_r2.json`。简单平均百分比误差在 JSON 中只对实测值大于零的条件计算，分母另列，不能与 WAPE 混用。

这些新工作集远小于 40 MiB L2，主要检验 L1 过滤和冷启动唯一地址计数。因此，本表 L2 读未命中完全匹配也不能验证 L2 容量边界、替换策略或写回行为。

容量边界仍不匹配：104 KiB、默认 32 KiB 共享划分、同向顺序扫描时，硬件 5 次 L2 读 sector 为 12672/13424/12768/13360/13760，而 96 KiB LRU 模型预测 26624。硬件保留部分命中，理想 LRU/FIFO 容量模型产生更陡的失效转折。不能以平均误差下降代替这个失配的修正。

另有 6 个并发条件 × 4 个配置的 24 次对照，保留全部计数与模拟 cycles。NCU 时长为插桩诊断，未锁频，不能据此唯一确定物理 MSHR。仍需联合请求合并、队列背压、调度和延迟，区分可观测行为相同的参数组合。本轮也没有验证 L2 写回模型、真实大语言模型算子或 hbserve + memgen 端到端流量。

下一步应针对容量边界保留部分命中的行为、缓存行/sector 的分配与替换粒度，以及并发重复地址请求的合并做模型改进；随后沿用这些完整条件和新的留出算子验证。当前支持的 LRU/FIFO 配置开关不足以表达所有观测，不能虚构一个不存在的配置选项来宣布完成。
